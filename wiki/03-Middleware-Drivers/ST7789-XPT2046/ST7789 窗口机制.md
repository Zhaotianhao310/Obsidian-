# ST7789 窗口机制

## 概念一句话精炼

ST7789 绘图采用“设置列窗口 CASET → 设置行窗口 PASET → RAMWR 连续写像素”的显存寻址机制，先开窗再灌像素是局部绘图和 DMA 刷新的共同基础；关联 [[ST7789 初始化时序]] 与 [[ST7789 DMA 刷屏]]。

## 核心原理与图解

```mermaid
flowchart LR
    A[应用绘图区域\nx0,y0 到 x1,y1] --> B[CASET 0x2A\n设置 X 范围]
    B --> C[PASET 0x2B\n设置 Y 范围]
    C --> D[RAMWR 0x2C\n进入像素写入状态]
    D --> E[RGB565 像素流\n高字节先发]
    E --> F[控制器自动递增\n填满窗口后停止]
```

> 图 1：ST7789 将二维绘图区转换为连续像素流；窗口边界决定像素写入的起点、终点和自动递增范围。

### 地址与数据规则

| 命令 | 地址 | 作用 | 后续数据 |
|---|---:|---|---|
| `CASET` | `0x2A` | 设置列/X 地址范围 | `x0`、`x1`，各 16 bit，高字节先发 |
| `PASET` | `0x2B` | 设置行/Y 地址范围 | `y0`、`y1`，各 16 bit，高字节先发 |
| `RAMWR` | `0x2C` | 声明后续为显存像素流 | RGB565 像素，按窗口顺序自动写入 |

窗口像素数为：

```text
pixel_count = (x1 - x0 + 1) × (y1 - y0 + 1)
byte_count  = pixel_count × 2       // COLMOD=0x55 时每像素 2 字节
```

## 关键实现与数据结构

以下为窗口建立的伪代码；`lcd_write_cmd` 和 `lcd_write_data16` 是工程自定义封装，不是官方 API。

```c
void ST7789_SetWindow(uint16_t x0, uint16_t y0,
                      uint16_t x1, uint16_t y1)
{
    lcd_write_cmd(0x2A);          // CASET：列范围
    lcd_write_data16(x0); lcd_write_data16(x1);
    lcd_write_cmd(0x2B);          // PASET：行范围
    lcd_write_data16(y0); lcd_write_data16(y1);
    lcd_write_cmd(0x2C);          // RAMWR：开始连续写像素
}
```

### 为什么必须高字节先发

SPI 本工程按 8 bit 传输，而 ST7789 的地址和 RGB565 像素逻辑上是 16 bit。发送 `0x1234` 时应先发 `0x12`，再发 `0x34`；如果字节序反了，窗口边界或颜色值都会错误。

## 横向对比与关联

| 绘图方式 | 传输组织 | 优点 | 代价 |
|---|---|---|---|
| 单像素绘图 | 每个像素单独开 1×1 窗口 | 实现简单 | CS/命令开销大，适合少量点 |
| 矩形填充 | 一次开窗，连续发送多行颜色 | 适合背景、控件区域 | 需要行缓冲区或重复颜色 |
| 图片/DMA | 一次开窗，分块发送像素流 | CPU 占用低、吞吐高 | 需要处理 DMA 忙状态和缓冲区生命周期 |

- [[XPT2046 触摸采样与坐标校准]]：触摸坐标最终要映射到同一套显示像素坐标域。
